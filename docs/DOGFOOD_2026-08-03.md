## What the workflow taught us

The reviewer reported that the selected manifest and schema file did not show
how `handoff_verify_return` maps to `VERIFY_SCHEMA`. The complete repository
does contain that mapping in `hermes_integration/__init__.py`, which was outside
the packet. The receipt proved that the returned file existed, had the recorded
digest, and contained the claimed section; it did not prove that the reviewer's
conclusion was globally correct.

That is the intended boundary in practice: receipts make evidence inspectable
and repeatable, but selecting enough context and judging the conclusion remain
controller responsibilities.

The run also exposed a real operator-experience gap: the native CLI did not
offer a concise structural review of the packet before approval. The release
preparation adds `hermes agent-trust review <handoff-id>` so the operator can
inspect the stored task, commit, archive digest, exact file list, and bounded
local paths before making the approval decision.
